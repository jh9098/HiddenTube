# HiddenTube
유튜브 자동생성 saas
1. 시스템의 전체 구조: "AI 콘텐츠 공장" 오팔 같은 툴을 만든다는 것은 단순히 영상을 만드는 것이 아니라, **여러 명의 AI 직원(에이전트)에게 업무를 배분하고 관리하는 '관리자 시스템'**을 만드는 것과 같습니다. • 프론트엔드(UI): 사용자가 명령을 내리고 에이전트들을 배치하는 작업 공간입니다. • 백엔드(Logic): 각 에이전트가 어떤 AI 모델(제미나이, Veo 등)과 연결될지 결정하고 데이터를 전달합니다. • 데이터베이스(DB): 대본, 이미지 경로, 업로드 상태 등을 저장하는 창고입니다 (초기엔 구글 시트 활용 가능). -------------------------------------------------------------------------------- 2. UI 구성 요소: "도마, 도구, 카운터" 오팔의 UI는 요리 과정에 비유하면 이해가 빠릅니다. • 캔버스 (Canvas/도마): 에이전트(노드)들을 올리고 선으로 연결하는 넓은 작업 영역입니다. (개발 시 React Flow 같은 라이브러리를 사용하면 구현이 쉽습니다.) • 노드 사이드바 (Tool Drawer/도구 서랍): 에이전트들의 종류를 고르는 곳입니다. ◦ 입력(Input): 주문서 역할 (예: 주제 입력창). ◦ 생성(Generate): 요리사 역할 (LLM, 이미지/영상 생성 모델). ◦ 자산(Asset): 재료 창고 역할 (외부 링크, 이미지 파일 등). ◦ 출력(Output): 완성된 접시 역할 (결과물 표시 및 업로드). • 속성 패널 (Counter/카운터): 선택한 에이전트에게 구체적인 프롬프트(명령어)를 넣거나 설정값을 바꾸는 곳입니다. -------------------------------------------------------------------------------- 3. 핵심 에이전트(기능) 배치 로직 직접 구현하실 때 각 노드(에이전트)는 다음과 같은 순서로 데이터를 주고받아야 합니다. 1. 연구 에이전트: 웹 서치 도구를 사용하여 최신 트렌드를 분석하고 정보를 수집합니다. 2. 시나리오 에이전트: 연구 결과를 바탕으로 영상을 여러 개의 **장면(Scene)**으로 나눕니다. (보통 6개 내외 추천) 3. 대본 추출 에이전트: 시나리오에서 배경 설명은 빼고 나레이션 대본만 정확히 뽑아냅니다. 4. 비주얼 에이전트: 대본에 맞는 이미지와 영상을 생성합니다. 이때 Veo 3.1 같은 모델을 호출합니다. 5. 보이스 에이전트: AudioLM이나 TTS 모델을 통해 나레이션을 소리로 바꿉니다. 6. 합성 및 업로드 에이전트: 모든 소스를 하나로 합쳐 유튜브 API를 통해 배포합니다. -------------------------------------------------------------------------------- 4. 데이터의 흐름 (Data Flow) 비전공자 입장에서 가장 중요한 것은 **"데이터가 어떻게 선을 타고 이동하는가"**입니다. • JSON 데이터 전송: 모든 노드는 정보를 JSON 형식으로 주고받습니다. 예를 들어, '주제' 노드에서 "건강 뉴스"라고 쓰면, 이 텍스트가 다음 '연구' 노드로 전달되어 AI가 검색을 시작하는 식입니다. • 구글 시트 연동: 각 단계의 결과(제목, 대본, 영상 링크 등)를 구글 시트의 컬럼에 실시간으로 기록하면 관리가 매우 편리해집니다. -------------------------------------------------------------------------------- 5. 수익화 및 배포를 위한 SaaS 설계 (최종 목표) 단순히 혼자 쓰는 툴을 넘어 프로그램 배포 수익을 내려면 다음 구조가 추가되어야 합니다. • 사용자 인증(Login): 각 사용자가 본인의 채널을 연결할 수 있어야 합니다. • API 키 관리: 사용자가 자신의 AI 서비스 키를 입력하게 하거나, 운영자가 제공하는 크레딧 기반 시스템을 구축합니다. • 스케줄링(Trigger): 매일 정해진 시간에 자동으로 리서치부터 업로드까지 실행되도록 하는 '트리거' 기능이 핵심입니다. 정리하자면, 1단계로 구글 시트를 DB로 활용하여 파이썬 코드로 각 AI API를 연결하는 로직을 먼저 만드세요. 2단계로 이를 **웹 UI(캔버스 형태)**로 시각화하여 사용자가 쉽게 조작할 수 있게 만들면, 오팔과 같은 강력한 자동화 SaaS를 완성하실 수 있습니다.

## 스킬 기반 규격 관리 적용

프로젝트에 스킬 기반 검증 워크플로우를 추가했습니다.

### 1) 규칙 저장
```bash
npm run manage-skills -- "우리 프로젝트의 리액트 컴포넌트 네이밍 규칙과 폴더 구조 표준"
```

위 명령은 `skills/verify-implementation/references/project-rules.md`에 규칙을 누적 저장합니다.

### 2) 구현 검증
```bash
npm run verify-implementation
```

다음을 자동 점검합니다.
- React 컴포넌트 파일명 PascalCase 여부
- 파일 길이(260줄 초과) 경고
- Cloud Firestore 읽기 관련 패턴(getDoc/getDocs/onSnapshot/collection)

### 3) 스킬 문서 위치
- `skills/verify-implementation/SKILL.md`
- `skills/verify-implementation/references/firestore-read-checklist.md`
- `skills/verify-implementation/references/project-rules.md`
